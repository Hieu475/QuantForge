# quantforge-llm

(Distribution name `quantforge-llm`; the import name is `quantforge`. Do not install it next to the unrelated PyPI package `quantforge` (an option-pricing library), which uses the same module name.)

INT4 / INT8 / FP8 GEMM kernels for LLM inference on NVIDIA GPUs (sm_80 and newer), generated by an MLIR compiler, with the PyTorch / vLLM integration to use them:

* **vLLM plugin** (`quantization="quantforge"`): loads 4-bit GPTQ and AWQ checkpoints (tensor parallelism, fused q/k/v and gate/up, `desc_act`, asymmetric zero points) and runs
  every linear layer on the generated kernels, also under `torch.compile` and CUDA graphs. `quantization="quantforge_w4a8"` runs INT4 weights with INT8 activations on the INT8 tensor cores.
* **PyTorch**: `quantforge.nn.quantize_model` (round-to-nearest), `quantforge.gptq.quantize_model_gptq` (GPTQ), `torch.ops.quantforge.w4a16_gemm`,
  `quantforge.gptq_checkpoint.save_gptq` (write a quantised model as an ordinary GPTQ checkpoint).
* **Kernel packs**: the compiler (LLVM / MLIR 18) is only needed to *make* kernels. `quantforge-pack` builds, ships and installs ready-made kernels for the layer shapes of a model,
  so a serving machine needs neither LLVM nor `nvcc`.

```bash
pip install quantforge-llm                 # needs a CUDA build of torch (and vLLM for the plugin)
quantforge-pack install <pack.tar.gz | https URL>     # ready-made kernels (or build your own: see below)
quantforge-doctor                          # GPU, toolchain, kernel packs; runs one kernel against a reference
python -c "from vllm import LLM; LLM('Qwen/Qwen2.5-1.5B-Instruct-GPTQ-Int4', quantization='quantforge', dtype='float16')"
```

Without a pack the kernels are compiled on first use, which needs the `quantforge-opt` tool, built with CMake against LLVM / MLIR 18 (see the repository), and the CUDA toolkit:
`export QUANTFORGE_BUILD_DIR=/path/to/build`. To make a pack on such a machine:
`python -m quantforge.pack build --out ./pack --model <Hugging Face id> [--w4a8]`, then `... pack ext --out ./pack`, `... pack check ./pack --model <id>`, `... pack archive ./pack pack.tar.gz`.
A layer shape that is in no pack and cannot be compiled still works: the op falls back to a dense torch path (slow, with a warning).

## What to expect

Measured on one RTX 4050 laptop GPU (6 GB, sm_89), vLLM 0.25, Qwen2.5 and Llama-3.2 checkpoints; other GPUs are untested (the kernels are PTX, so any sm_80+ card runs them,
but the tile choices were tuned on this one and the planners measure per GPU). Decode throughput against vLLM's Marlin on the same GPTQ checkpoint, Qwen2.5-1.5B:
about 0.92-0.94 of Marlin from 1 to 16 concurrent requests, 0.85-0.9 at 32-256; prefill is 0.90-0.92x of Marlin (W4A8: 1.07-1.14x). The W4A8 path (INT8 activations, different numerics: round-to-nearest or GPTQ-quantised W4A8 weights)
reaches 1.06x of Marlin at 192-256 concurrent requests. Details, methodology and the negative results are in the repository README and CHANGELOG:
<https://github.com/Hieu475/QuantForge>, notes at <https://hieu475.github.io/>.

Alpha software: tested on Linux, Python 3.12, torch 2.11 (CUDA 12.8) and 2.15, vLLM 0.25 / 0.34. Mixture-of-experts: 4-bit silu-gated experts, run end to end on one model (OLMoE) only. No act-order checkpoint writing, no AMD / Apple GPUs.
